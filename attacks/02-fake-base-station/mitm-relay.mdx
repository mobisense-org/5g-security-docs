## Attack Mechanism

A full MITM relay gNB acts as a transparent proxy between the victim UE and the real network. One SDR faces the UE (acting as a fake gNB), while the second SDR faces the real network (acting as a rogue UE).

```
                   SDR #1              SDR #2
  Victim UE  <──>  Fake gNB  ──────>  Fake UE  <──>  Real gNB
              Air Interface          Internal         Air Interface
              (rogue cell)           Relay            (legitimate)
```

### Attack Steps

```
1. SDR #1 broadcasts SSB/SIB1 mimicking the target cell (higher power)
2. Victim UE attaches to the rogue cell
3. All UE messages are received by SDR #1 and forwarded via SDR #2 to real gNB
4. All downlink messages from real gNB are received by SDR #2 and relayed to UE
5. Attacker can inspect, modify, drop, or inject messages in transit
6. Pre-authentication messages (RRC) are fully visible and modifiable
7. Post-authentication: NAS is encrypted, but RRC manipulation remains possible
```

<Warning>
This is the most powerful but also most complex fake base station attack. Timing synchronization between the two SDRs is critical and requires careful calibration.
</Warning>

### Capabilities Once Established
- RRC message manipulation (capability stripping, redirect, release)
- Downgrade attacks via modified UE capability information
- Measurement report interception for location tracking
- NAS message inspection (pre-authentication)

## Replication

| Component | Requirement |
|---|---|
| SDR (UE-facing) | USRP B210 — acts as rogue gNB |
| SDR (Network-facing) | USRP B210 — acts as rogue UE |
| Amplifier | PA for the UE-facing side |
| Software | Custom 5G NR relay stack (srsRAN-based or OAI-based) |
| Clock | Shared 10 MHz reference between both B210s recommended |
| Compute | High-end workstation (real-time PHY processing for both links) |

<Tip>
The primary engineering challenge is maintaining real-time relay with acceptable latency. The 5G NR HARQ timing budget is tight (typically 4-8 slots), leaving little room for processing delay.
</Tip>
