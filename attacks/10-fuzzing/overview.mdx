# Protocol Fuzzing

## Overview

Protocol fuzzing systematically generates malformed, unexpected, or random protocol messages to find parsing bugs, crashes, and logic errors in 5G implementations. This category has produced the most CVEs of any 5G security research area.

## Common Approach

Most 5G fuzzers follow this pattern:

1. **Model the protocol:** Build a state machine of the target protocol (NAS, RRC, NGAP, GTP, SBI).
2. **Generate mutations:** Create malformed messages by flipping bits, truncating fields, injecting invalid IEs, or violating ASN.1 encoding rules.
3. **Send and monitor:** Deliver mutations to the target implementation and monitor for crashes, hangs, memory corruption, or unexpected state transitions.
4. **Triage:** Classify findings by severity (crash = high, unexpected response = medium, etc.).

## Why 5G Is Particularly Fuzzable

- **ASN.1 PER encoding** is complex and error-prone to implement
- **Multiple independent implementations** (srsRAN, OAI, Open5GS, Magma, free5GC) each have unique bugs
- **Large protocol surface** -- NAS alone has dozens of message types with hundreds of optional IEs
- **Open-source availability** makes white-box and grey-box fuzzing straightforward

## Getting Started

The easiest entry point is fuzzing Open5GS or srsRAN in a local Docker environment. RANsacked's ASNFuzzGen tool can auto-generate fuzzers from 3GPP ASN.1 specifications.
