## Summary

5G's Service-Based Architecture (SBA) replaces the LTE EPC's point-to-point Diameter signaling with REST APIs over HTTP/2, with OAuth2 tokens issued by the NRF authorizing every NF-to-NF call. This made the 5G core operationally a microservices web app — and inherited every microservices-web-app weakness: token replay, scope confusion, weak input validation, missing TLS, rate-limit gaps, SSRF, injection. The 5G core is now where the bugs are.

## Threat Model

| | |
|---|---|
| **Attacker** | Network-attached attacker with IP reach to SBI endpoints (e.g., compromised NF, malicious workload in the same K8s namespace, foothold on operator transport) |
| **Victim** | Any of: AMF, SMF, AUSF, UDM, NRF, NEF, etc. — every NF exposes REST APIs |
| **Position** | IP layer; no radio, no UE |
| **Capability** | Send arbitrary HTTP/2 to SBI endpoints; replay or forge OAuth2 tokens; inject malformed JSON / SBI parameters |
| **Pre-requisite** | Either: (a) sit on the operator's SBA network, or (b) compromise a single NF and pivot |

## Attack Mechanism

The 5GC's REST endpoints (3GPP TS 29.5xx series) are HTTP/2 + JSON. The bugs split into four classes:

1. **Missing TLS / weak TLS**: many lab and some production cores expose SBI in cleartext. Sniff the network → forge any call.
2. **Token misuse**: OAuth2 access tokens issued by NRF authorize "AMF→SMF for service X" but receivers validate scope loosely → replay against service Y (see [Cross-Service Token](/attacks/14-20-specialized/cross-service-token)).
3. **Input validation gaps**: SQL/NoSQL injection on the backing data store; SSRF via callback URLs in 3GPP API parameters; integer/buffer issues in parsers.
4. **No rate-limit**: NRF lookup, AMF status APIs, etc. accept unbounded request rates → trivially DDoS-able from a single NF.

## Replication

- **Lab setup**: Open5GS in Kubernetes (or Docker-Compose). Tools: Burp Suite, OWASP ZAP, `httpx`, `nuclei`, and the [5GC Pen-Test arXiv paper](https://arxiv.org/abs/2403.01871) as the playbook.
- **No SDR, no radio** — pure HTTP-layer testing.
- **Where to find bugs fast**: NRF service discovery (`/nnrf-disc/v1/nf-instances`), AMF UE context (`/namf-comm/v1/ue-contexts/`), UDM subscription (`/nudm-sdm/v2/{supi}/...`).
- **Production-realistic test**: stand up Open5GS with TLS enabled, OAuth2 enforcement on, then try the bug catalog from the paper — many still trigger because of validation gaps.

## RF Signature

**No RF signature.** SBA traffic rides on the operator's IP transport between Network Functions — nothing on the radio. A passive RF sniffer sees nothing for this entire row.

If your defense thesis is "passive RF + AI," **explicitly out-of-scope for the primary detector**. SBA defense lives in API gateways, service meshes, and observability of HTTP/2 traffic between NFs.

## Detection (operator side)

- API gateway / service mesh (Istio, Envoy) with rate-limiting, mTLS enforcement, JWT validation per-call.
- NRF audit log: every token issued + every cross-NF call. Anomaly detection on caller/callee/scope tuples.
- Standard web-app pen-test hygiene applied to NF endpoints.
