## Summary

CONSET (USENIX Security '26) uses LLMs to parse 3GPP specifications, extract semantic constraints, and generate test cases that **violate the intended semantics** of the protocol — not just the syntax. Where classical fuzzers (5GHOUL, 5GBaseChecker) catch parser bugs, CONSET catches **logic** bugs: messages that are syntactically valid but semantically illegal under the current protocol state. The framework discovered 3 high-severity CVEs affecting 41 chipsets and over 466 phone models. Source code is not yet publicly available.

## Threat Model

| | |
|---|---|
| **Attacker** | Rogue gNB delivering semantically-crafted pre-auth messages |
| **Victim** | UE modem (baseband firmware) |
| **Position** | Within radio range of victim UE |
| **Capability** | Standard rogue-gNB infrastructure + LLM-generated payloads |
| **Pre-auth?** | Yes — same delivery channel as 5GHOUL but smarter content |
| **Novelty** | The **content** is novel, not the delivery — bugs depend on protocol *state*, not parser quirks |

## Attack Mechanism

1. **Spec ingestion (offline)**: an LLM pipeline reads 3GPP TS 38.331 (RRC), 24.501 (NAS), and related specs. It extracts preconditions, postconditions, and forbidden combinations.
2. **Test generation**: the framework generates candidate messages that are syntactically valid (pass ASN.1 PER decode) but violate at least one semantic constraint — e.g., a `RRCReconfiguration` with a field combination that the spec explicitly disallows from the current RRC state.
3. **Delivery (online)**: same channel as 5GHOUL — a rogue gNB attracts the UE and sends the generated messages in the pre-auth window.
4. **Oracle**: modems crash, hang, or transition to undefined states. Many implementations only check syntax (ASN.1 PER) and skip semantic validation, so semantically-illegal payloads slip through.

## Replication

- **Code not public** as of acceptance. The authors may release after publication.
- **LLM dependency**: the spec-parsing step requires a capable LLM (paper doesn't specify which); reproducing the test corpus from scratch is non-trivial.
- **Delivery hardware**: standard rogue gNB (B210 + srsRAN/Open5GS) — same as 5GHOUL.
- **Practical replication path before code release**: read the paper, manually identify a few semantic violations in TS 38.331, encode them, and deliver via 5GHOUL's infrastructure. You'll reproduce a subset but not the full corpus.

## RF Signature (passive RF + AI)

Same rogue-gNB signature as 5GHOUL — a passive sniffer with PCI/SIB-fingerprint AI catches the **delivery infrastructure** regardless of the payload smartness. The semantic payloads themselves are harder to flag with simple anomaly detection because they parse cleanly:

- **Pre-auth RRC content sequences** are the discriminator. AI angle: sequence model trained on legitimate-operator RRC traces vs. CONSET-style state-violating sequences. This is roughly the same problem class as protocol-aware IDS — feasible but harder than catching syntactic anomalies.
- The novel research question: **can passive RF + AI detect semantic violations the modem itself misses?** Open problem — exactly the kind of work the lab would want to attempt.

## Detection (gNB / core side)

- Stricter spec-compliance validation at the gNB before forwarding pre-auth content (effectively, build the spec-aware checks the modem skipped).
- Anomaly detection on per-UE RRC message sequences at the AMF.
