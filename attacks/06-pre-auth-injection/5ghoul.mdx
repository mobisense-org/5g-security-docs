## Summary

5GHOUL is a pre-authentication exploitation framework targeting commercial 5G NR modems from Qualcomm and MediaTek. It packages 22+ known vulnerabilities (14 disclosed initially in Dec 2023, more added through 2024) into a single Docker container that runs against any nearby UE — no SIM card, no operator coordination. The all-in-one Docker + B210 setup makes it the **easiest published 5G attack to reproduce in a lab**.

|---|---|

| **Victim** | UE modem (baseband firmware) |
| **Position** | Within radio range of victim UE (typically < 10 m for unamplified B210; further with PA) |
| **Capability** | Broadcast SSB/MIB/SIB1 of a fake cell at higher RSRP than legit cells; respond to RACH with crafted pre-auth RRC/NAS |
| **Pre-auth?** | Yes — bugs trigger before AKA, no SIM needed |
| **Persistence** | Some bugs require victim reboot to recover; others auto-recover after timeout |

## Attack Mechanism

5GHOUL operates a minimal rogue gNB that broadcasts legitimate-looking SSB and MIB/SIB1 to attract nearby 5G UEs. When a UE initiates the RACH procedure:

1. 5GHOUL accepts the RACH and responds with crafted Msg2/Msg4.
2. During the post-RACH RRC/NAS exchange, it injects fuzzed or malformed messages.
3. Because the security context is not yet established, the modem firmware parses these messages without integrity checking.
4. The bugs — buffer overflows, assertion failures, state-machine violations — cause crashes, persistent DoS, or forced fallback to LTE.

The 22+ catalogued CVEs cover three vulnerability classes: parsing bugs in ASN.1-coded RRC/NAS, state machine inconsistencies, and integer overflows in MAC-layer length fields.

## Replication

The Docker container is one `docker run` away from a working attack:

```bash
git clone https://github.com/asset-group/5ghoul-5g-nr-attacks
cd 5ghoul-5g-nr-attacks
./run.sh   # builds + starts the Docker stack with srsRAN + Open5GS
# In another shell:
./fuzz_5g.sh <CVE_ID>   # pick from the menu
```

Then power on a target Qualcomm/MediaTek 5G phone with airplane mode off, within ~5 m of the B210 antenna. Most exploits trigger within seconds of the UE camping on the rogue cell.

**No PA required** for short-range lab testing. Adding a 1 W PA on n78 gets you tens of meters; check local regulations.

## RF Signature (passive RF + AI)

5GHOUL is one of the **easiest classes of attack to detect** via a passive RF sniffer:

- **New PCI on an unexpected band**: a sniffer with a baseline of the operator's legitimate PCIs flags a foreign cell instantly.
- **SIB1 content fingerprint**: 5GHOUL's SIB1 typically uses srsRAN defaults — barring/priority/scheduling fields differ from carrier production gear. AI angle: classifier trained on operator-baseline SIB1 vs. arbitrary content.
- **Anomalous pre-auth RRC content**: the fuzzed payloads themselves are out-of-spec — many fields use values that the operator never sends.
- **Bursty RACH→teardown→reattach cycles** on the victim UE if the attack crashes the modem.

A passive defender with a B210-class sniffer + a basic ML classifier on PCI + SIB content should catch a 5GHOUL gNB within seconds of it transmitting.

## Detection (UE / OS / operator side)

- Mobile OS: monitor for unexpected PLMN/PCI changes; flag connections that immediately drop into limited-service.
- Operator: anomalous UE reattach storms in specific cells; "phantom" PCIs reported via measurement reports.
